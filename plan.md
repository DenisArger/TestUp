# План: Админ-панель для тестов на PocketBase

## Контекст

Пользователь создал в PocketBase три коллекции для тестов:
- `quizzes` (pbc_93315167): title, description, active
- `questions` (pbc_4009210445): quiz_id (relation, cascade delete), text, type (select: single/multiple/text), options (JSON array), correct_answer
- `attempts` (pbc_4287217533): tg_id, quiz_id (relation), score, total

Текущее состояние: бэкенд запускается через `start.sh` (`./pocketbase serve --http=0.0.0.0:8090`), миграции применены, фронтенда нет, ACL-права открыты (null).

## Цель

Создать удобную веб-админ-панель для создания/редактирования вопросов и отображения результатов прохождения.

## Принятые решения

1. **Тип админки**: кастомная веб-панель через REST API PocketBase.
2. **Аутентификация**: через админ-аккаунт PocketBase (POST /api/admins/auth-with-password, сессия через cookie).
3. **Управляемые сущности**: тесты (quizzes, CRUD), вопросы (questions, CRUD), результаты (attempts, только чтение).
4. **Размещение**: отдельная статическая папка `admin_panel/` с проксированием API (вариант A — отдельный статический сервер, например, python http.server на порту 8080, тот же хост).
5. **Редактирование options**: визуальный редактор (чекбоксы/радио) вместо ручного JSON.

### Подключение к PocketBase

PocketBase — compiled binary без исходников, поэтому кастомные роуты через Go-плагин недоступны. Используем отдельный статический сервер.

**Выбранный вариант**: отдельная статическая папка `admin_panel/`, запускаемая отдельно (например, `python3 -m http.server 8080 --directory admin_panel`) на порту 8080, тот же хост. Админка обращается к API по `http://localhost:8090/api/...`.

**Запуск**: в `start.sh` добавить запуск статического сервера после PocketBase (или инструкция запускать оба вручную/через systemd).

### Структура REST API (уже доступна)

| Операция | Endpoint | Метод |
|----------|----------|-------|
| Вход администратора | `/api/admins/auth-with-password` | POST (identity, password, возвращает cookie) |
| Список тестов | `/api/collections/quizzes/records` | GET |
| Создать тест | `/api/collections/quizzes/records` | POST |
| Обновить тест | `/api/collections/quizzes/records/{id}` | PATCH |
| Удалить тест | `/api/collections/quizzes/records/{id}` | DELETE |
| Список вопросов (с фильтром по quiz_id) | `/api/collections/questions/records?filter=quiz_id="{id}"` | GET |
| Создать/обновить/удалить вопрос | аналогично | CRUD |
| Список результатов (с фильтром по quiz_id) | `/api/collections/attempts/records?filter=quiz_id="{id}"` | GET |
| Расширить вопрос о тесте | `/api/collections/questions/records/{id}?expand=quiz_id` | GET |

### Дизайн формы вопроса

Вопрос имеет поля:
- `text` — текст вопроса (plaintext, required)
- `type` — тип (select: single/multiple/text)
- `options` — массив вариантов (JSON). Редактируется как список строк.
- `correct_answer` — правильный ответ:
  - для `single`: индекс выбранного варианта (строка, например "0")
  - для `multiple`: массив индексов (например, "[0, 2]") или строка с разделителями
  - для `text`: ключевое слово/фраза

**Редактор вариантов**:
- Поле "Варианты ответа" — список строк, каждая строка = текст варианта.
- Кнопка "Добавить вариант" — добавляет пустую строку.
- Кнопка "Удалить вариант" — удаляет строку.
- При `type=single` — радио-кнопки для выбора правильного ответа (индекс).
- При `type=multiple` — чекбоксы, можно выбрать несколько.
- При `type=text` — поле "Правильный ответ" как текст.

### Дизайн страницы результатов

- Выпадающий список тестов (quizzes) для фильтрации.
- Таблица результатов:
  - Telegram ID
  - Название теста (через expand)
  - Набранный балл
  - Максимальный балл
  - Процент правильных ответов (вычисляется на фронте: score/total*100)
  - Дата прохождения (created)
- Возможна сортировка по дате/баллу.

## Риски и ограничения

1. **ACL-права**: все коллекции имеют `null` для listRule/createRule и т.д. — это означает открытый доступ. Для production нужно ограничить доступ к API через Rules в настройках коллекций (например, только для администратора). В плане не изменяем ACL — это отдельная задача.
2. **Сессия администратора**: cookie сессии может истекать. Реализовать автоматический logout при 401.
3. **Одновременность**: без блокировок при редактировании — базовый функционал.
4. **Безопасность**: пароль администратора должен храниться в безопасном месте, не в коде фронтенда.
5. **Каскадное удаление**: в миграции `questions` уже настроено `cascadeDelete: true` для `quiz_id`. При удалении теста вопросы удалятся автоматически.
